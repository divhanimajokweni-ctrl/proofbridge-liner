## Abstract

The **Epistemic DAG Runtime** is a novel distributed systems framework that fuses **invariant-preserving CRDT convergence**, **autonomous convex constraint optimization**, and **zero-knowledge cryptographic proofs** into a unified, production-grade runtime. It enables multiple autonomous agents to fork, evolve, and merge their states under mathematically guaranteed physical and logical invariants. When violations occur, the system does not merely reject—it heals itself through bounded optimization and generates privacy-preserving Groth16 proofs that the repair was performed correctly. This document serves as the complete technical specification covering architecture, components, algorithms, APIs, and verification methodology.

## 2. Core Engine: Epistemic DAG

### 2.1 Data Structure

The Epistemic DAG is a **directed acyclic graph** where:

- **Nodes** = Merge commits, each containing: agent ID, policy ID, state vector (JSON), parent references, Lamport clock value
- **Edges** = Causal relationships between merges
- **Roots** = Initial state commitments (genesis merges)
- **Leaves** = Most recent unmerged states (agent forks)

### 2.2 Merkle Mountain Range (MMR) Indexing

The DAG's commit history is indexed by a **Merkle Mountain Range**—a commitment structure that supports:

- **Efficient appends**: O(log n) to add a new commit
- **Inclusion proofs**: O(log n) to prove a commit is in the DAG
- **Zero-knowledge ancestry**: Prove descent from a known root without revealing intermediate commits
- **Gap-resistant**: Unlike Merkle trees, MMRs don't require a balanced structure

#### MMR Operations

```
APPEND(leaf):
add leaf as new peak
while last two peaks have same height:
merge them into a parent peak
return new root hash

PROVE_INCLUSION(leaf_index):
collect sibling hashes along the path to root
return (leaf, siblings, root)

VERIFY_INCLUSION(leaf, siblings, root):
recompute peak hashes from leaf upward
return computed_root == root
```

### 2.3 CRDT Convergence Guarantees

The DAG provides **Strong Eventual Consistency (SEC)** with the following guarantees:

- **Convergence**: All agents that see the same set of merges eventually compute the same state
- **Invariant Preservation**: No convergent state can violate a declared invariant
- **Causal Consistency**: Merges respect Lamport clock ordering
- **Merge Commutativity**: The order of concurrent merges does not affect the final state (for independent variables)

### 2.4 Lamport Clock Ordering

Each agent maintains a logical clock. On every merge proposal:

```
agent_clock = max(agent_clock, max(parent_clocks)) + 1
```

Merges are ordered by `(lamport_clock, agent_id)` to break ties deterministically.

### 3.1 Grammar

```

[shadow {

takeover: <boolean_expression>
}]

[sharding {
regions: [<string>, ...]
strategy: <pin | balance | locality>
}]

[ancestry {
require: <number>
anchored: <boolean>
}]

[export {
format: <json-ld | csv | proof>
target: <string>
frequency: <number>
}]
}
```

### 3.2 Expression Language

| Category | Operators | Example |
|----------|-----------|---------|
| Arithmetic | `+`, `-`, `*`, `/` | `temperature - setpoint` |
| Comparison | `>=`, `<=`, `>`, `<`, `==`, `!=` | `frequency >= 49.8` |
| Logical | `and`, `or`, `not` | `freq >= 49.8 and freq <= 50.2` |
| Absolute | `abs()` | `abs(rocof) < 0.5` |
| Aggregation | `sum()`, `avg()`, `max()`, `min()` | `sum(loads) <= capacity` |

### 3.3 Parser Architecture

The parser uses a **recursive descent** approach with three stages:

1. **Lexer** (`tokenize`): Converts source string → token stream
2. **Parser** (`parseEPD`): Converts token stream → AST
3. **Compiler** (`compileInvariantsToConstraints`): Converts AST → executable constraint functions with gradients

### 3.4 AST Structure

```typescript
interface PolicyAST {
name: string;
invariants: InvariantNode[];
repair?: RepairConfig;
shadow?: ShadowConfig;
sharding?: ShardingConfig;
ancestry?: AncestryConfig;
export?: ExportConfig[];
}

interface InvariantNode {
name: string;
predicate: ExpressionNode;
}

interface RepairConfig {
variables: RepairVariable[];
maxTotalCost?: number;
}

interface RepairVariable {
name: string;
minRange: number;
maxRange: number;
cost: number;
}
```

### 3.5 Constraint Extraction

The compiler maps invariant expressions to executable constraint functions that expose both `evaluate(state)` and `gradient(state)` methods, enabling gradient-based repair optimization.

## 4. Self-Repairing Merge Engine

### 4.1 Problem Formulation

Given:
- A proposed state vector **x̄** ∈ ℝⁿ
- A set of invariant constraints **gⱼ(x) ≥ 0** for j = 1...m
- A repair configuration specifying adjustable variables, ranges **rᵢ**, and costs **cᵢ**

Find **x*** that solves:

```
minimize Σᵢ cᵢ · (xᵢ - x̄ᵢ)²
subject to gⱼ(x) ≥ 0 ∀j ∈ {1...m}
-rᵢ ≤ xᵢ - x̄ᵢ ≤ rᵢ ∀i ∈ adjustable
```

If no feasible solution exists, return `null`.

### 4.2 Solver Algorithm

```
ALGORITHM: Damped Iterative Gradient Projection

Input: proposedState x̄, constraints[], repairConfig
Output: repairedState x* or null

PARAMETERS:
maxIterations = 250
dampingFactor = 0.4
epsilon = 1e-7

PROCEDURE:
x ← x̄
FOR iter = 0 TO maxIterations - 1:
violationFound ← false

FOR EACH constraint c IN constraints:
margin ← c.evaluate(x)
IF margin < -epsilon:
violationFound ← true
grad ← c.gradient(x)

// Compute weighted denominator
denom ← 0
FOR EACH (varName, gVal) IN grad:
IF varName IN adjustableVars:
denom ← denom + (gVal² / cost[varName])

IF denom > 1e-12:
stepMag ← dampingFactor * (-margin) / denom
FOR EACH (varName, gVal) IN grad:
IF varName IN adjustableVars:
x[varName] ← x[varName] + (stepMag * gVal) / cost[varName]

// BOUNDARY CLAMPING
FOR EACH variable v IN repairConfig.variables:
original ← x̄[v.name]
current ← x[v.name]
IF current > original + v.maxRange:
x[v.name] ← original + v.maxRange
ELSE IF current < original + v.minRange:
x[v.name] ← original + v.minRange

IF NOT violationFound:
BREAK

// FINAL VALIDATION
FOR EACH constraint c IN constraints:
IF c.evaluate(x) < -1e-5:
RETURN null

// COST CHECK
IF repairConfig.maxTotalCost EXISTS:
totalCost ← 0
FOR EACH variable v IN repairConfig.variables:
totalCost ← totalCost + |x[v.name] - x̄[v.name]| * v.cost
IF totalCost > repairConfig.maxTotalCost:
RETURN null

RETURN x
```

### 4.3 Merge Flow with Repair

```
PROCEDURE: handleMerge(agentId, policyId, proposedState, parentIds)

1. FETCH policy record from database
2. PARSE policy source into AST
3. COMPILE invariants into constraint functions
4. EVALUATE all constraints on proposedState
5. IF no violations:
CREATE merge commit with proposedState
RETURN { repaired: false, merge }
6. IF violations exist AND policy has repair config:
a. CREATE merge commit with proposedState (failed merge, preserved for audit)
b. RUN repair solver → healedState
c. IF healedState is null:
RETURN { error: "Unrepairable", violations }
d. COMPUTE adjustments and cost
e. CREATE merge commit with healedState (parent: failed merge)
f. CREATE repair record linking failed → healed
g. GENERATE ZK proof (if circuit compiled)
h. RETURN { repaired: true, repair, merge }
7. IF violations exist AND no repair config:
RETURN { error: "Invariant violation", violations }
```

### 4.4 Determinism Guarantees

- Fixed random seed (none used)
- Fixed iteration order over constraints (sorted by name)
- Damping factor constant across all runs
- Deterministic boundary clamping (no floating-point non-determinism in comparisons)
- Same `(proposedState, policy, config)` → identical `healedState` on any node

## 5. Zero-Knowledge Epistemic Proofs

### 5.1 Statement Proven

> *"I know a proposed state `x̄` and a repair execution trace such that the resulting state `x*` satisfies all invariants `gⱼ(x*) ≥ 0` and all adjustments `|xᵢ* - x̄ᵢ| ≤ rᵢ`, and the public commitments `H(x*)` and `H(config)` match."*

### 5.2 Circuit Architecture

```
PUBLIC INPUTS: H(x*), H(config), H(invariants)
PRIVATE INPUTS: x̄, x*, intermediate states, adjustment deltas

CIRCUIT: RepairSolver(nVariables, nConstraints, nIterations=64)
├── STATE INIT: state[0] ← x̄
├── UNROLLED LOOP (64 iterations):
│ ├── CONSTRAINT EVALUATION: gⱼ(state[i]) computed
│ ├── GRADIENT PROJECTION: state[i+1] ← state[i] + step
│ └── BOUND CLAMPING: |state[i+1] - x̄| ≤ r
├── FINAL CHECK: gⱼ(state[64]) ≥ 0 ∀j
├── ADJUSTMENT CHECK: |state[64] - x̄| ≤ r
└── COMMITMENT CHECK:
├── Poseidon(state[64]) == H(x*)
└── Poseidon(config) == H(config)
```

### 5.3 Per-Policy Circuit Compilation

When a `.epd` with a `repair` block is deployed:

1. **Parameter Extraction**: nVariables, nConstraints determined from repair config
2. **Circuit Generation**: Circom template instantiated with parameters
3. **Compilation**: `circom repair_solver.circom --r1cs --wasm`
4. **Trusted Setup**: Groth16 setup with Powers of Tau (phase 1 pre-computed)
5. **Key Extraction**: Verification key exported and stored in policy record
6. **Registration**: `policy.zkEnabled = true`, `policy.verificationKey = vk`

### 5.4 Proof Generation Flow

```
PROCEDURE: generateRepairProof(repairId, trace)

1. LOAD compiled circuit artifacts for the policy
2. CONVERT all state values to fixed-point integers (× 10⁶)
3. BUILD witness from solver trace
4. CALL snarkjs.groth16.fullProve(witness, wasm, zkey)
5. STORE proof and publicSignals in repair record
6. SET repair.zkVerified = true
7. RETURN { proof, publicSignals }
```

### 5.5 Verification

```
PROCEDURE: verifyRepairProof(repairId)

1. LOAD proof and publicSignals from repair record
2. LOAD verification key from policy record
3. CALL snarkjs.groth16.verify(vk, publicSignals, proof)
4. RETURN true/false
```

Any observer can verify—no access to private state required.

### 5.6 Circuit Metrics

| Metric | Typical Value |
|--------|---------------|
| Constraints (R1CS) | ~15,000 - 50,000 |
| Variables | nVariables × 65 (state trace) |
| Proving Time | ~2-5 seconds |
| Proof Size | ~128 bytes |
| Verification Time | ~2 milliseconds |
| Curve | BN128 |

### 6.2 Shadow Bridge Pattern

The Shadow Bridge runs the epistemic runtime in parallel with production systems:

| Mode | Description |
|------|-------------|
| **Shadow** | Runtime observes but does not control; logs discrepancies |
| **Advisory** | Runtime issues recommendations; human operator decides |
| **Guard** | Runtime blocks unsafe commands; operator override required |
| **Active** | Runtime takes full control on invariant violation |

Transition between modes is governed by the policy's `shadow` block.

### 6.3 Drift Monitoring

```
DRIFT(t) = max(0, distance_to_invariant_boundary(t) / ceiling)
```

- `DRIFT < 0.5`: Normal operation
- `0.5 ≤ DRIFT < 0.8`: Warning (amber)
- `0.8 ≤ DRIFT < 1.0`: Critical (red)
- `DRIFT ≥ 1.0`: Violation (shutdown/takeover)

## 7. Shard Rebalancing & Horizontal Scaling

### 7.1 Sharding Strategy

State space is partitioned across nodes using **invariant-aware sharding**:

- Each shard owns a subset of the state variables
- Cross-shard merges are governed by composable invariants
- MMR roots are maintained per-shard with cross-shard references

### 7.2 Rebalancing Algorithm

```
PROCEDURE: computeRebalance()

1. GATHER load metrics for all nodes (shard count, merge rate, violation rate)
2. IDENTIFY hottest node (max shards) and coolest node (min shards)
3. FOR EACH shard on hottest node:
a. SIMULATE migration to coolest node
b. VERIFY all invariants still satisfied
c. IF safe: ADD to candidate list
4. RETURN candidates sorted by safety margin
```

### 7.3 Migration Execution

```
PROCEDURE: migrateShard(shardId, fromNode, toNode)

1. VERIFY invariants pre-migration
2. LOCK shard on source node
3. COPY state + MMR to target node
4. UPDATE routing table
5. UNLOCK shard on target node
6. VERIFY invariants post-migration
7. IF invariant violated: ROLLBACK, return 409
8. RETURN success
```

## 8. Federation & Multi-Organization Protocol

### 8.1 Federation Model

Organizations run independent epistemic runtimes that can reconcile state through the `epistemic://` protocol:

```
┌──────────────┐ epistemic:// ┌──────────────┐
│ ORG Alpha │◄────────────────►│ ORG Beta │
│ (GridCo EU) │ handshake + │ (Health Fed) │
│ │ reconcile │ │
└──────────────┘ └──────────────┘
```

### 8.2 Handshake Protocol

1. **Discovery**: Organizations exchange root hashes
2. **Capability Negotiation**: Agree on shared invariant set
3. **Trust Establishment**: Exchange verification keys for ZK proof validation
4. **Channel Setup**: Establish reconciliation channels with agreed frequency

### 8.3 Cross-Org Reconciliation

```
PROCEDURE: reconcile(orgA, orgB)

1. EXCHANGE MMR roots
2. IDENTIFY divergent leaves
3. FOR EACH divergence:
a. Propose merge from each org's perspective
b. Validate against shared invariants
c. IF both valid: accept convergence
d. IF one invalid: requesting org repairs against shared invariants
e. GENERATE ZK proof of repair
f. VERIFY proof by counterparty
4. UPDATE local DAG with reconciled state
```

## 13. Formal Verification

### 13.1 TLA+ Specification

The convergence properties of the Epistemic DAG are formally specified in TLA+:

```tla
---- MODULE EpistemicDAG ----
EXTENDS Naturals, Sequences, FiniteSets

CONSTANTS Agents, Variables, Invariants

VARIABLE dag, agentStates

Init ≜
∧ dag = {}
∧ agentStates = [a ∈ Agents ↦ [v ∈ Variables ↦ 0]]

Merge(agent, state) ≜
LET
violations ≜ {inv ∈ Invariants : ¬inv(state)}
repaired ≜ IF violations ≠ {} THEN Repair(state, violations) ELSE state
IN
IF repaired ≠ None THEN
∧ dag' = dag ∪ {⟨agent, repaired⟩}
∧ agentStates' = [agentStates EXCEPT ![agent] = repaired]
ELSE
UNCHANGED ⟨dag, agentStates⟩

Convergence ≜
∀ a, b ∈ Agents :
◇(agentStates[a] = agentStates[b])

THEOREM Convergence
==========================
```

### 13.2 Convergence Theorem

> **Theorem**: For any set of agents that all observe the same set of merge proposals, and any policy with convex invariant constraints and a feasible repair configuration, all agents eventually converge to the same state.
>
> **Proof Sketch**: The repair solver is deterministic and produces a unique output for any given input. Since all agents run the same solver on the same proposals (guaranteed by the DAG's causal delivery), they all compute the same repaired states. The DAG's CRDT merge is commutative for independent variables, so the order of concurrent merges does not affect the final state.

### 13.3 Safety Theorem

> **Theorem**: No converged state can violate a declared invariant.
>
> **Proof**: The repair solver's final validation loop checks all constraints. If any constraint is violated, the solver returns `null` and no merge is committed. If a repair is applied, the healed state is validated before commitment.

Instead, the solver runs off-circuit to find the answer, and the circuit simply verifies that the final state is valid.To prove a repair transaction, the circuit only needs to verify three things:The repairedState satisfies all the original policy invariants.The delta between originalState and repairedState sits within the allowed minRange and maxRange boundary boxes.The total computed adjustment cost does not exceed maxTotalCost.Here is how we construct the arithmetic circuit layout and the proving pipeline using Circom and SnarkJS over the $BN254$ elliptic curve.1. The Arithmetic Circuit Layout (repair_verifier.circom)Because circuits operate on finite fields, we use a fixed-point scaling factor (e.g., scaling numbers by $10^5$) to handle decimals deterministically as integers.Code snippetpragma circom 2.1.6;

include "node_modules/circomlib/circuits/comparators.circom";

template StateRepairVerifier(nVariables) {
// Public Inputs (What the world/dashboard sees)
signal input originalStateHash;
signal input policyInvariantsHash;
signal input maxTotalCost;

// Private Witness Inputs (The raw values hidden or checked inside the runtime)
signal input originalState[nVariables];
signal input repairedState[nVariables];
signal input variableCosts[nVariables];
signal input minRanges[nVariables]; // Represented as offset integers
signal input maxRanges[nVariables];

// Outputs
signal output isValidRepair;

// Constants & Intermediates
signal totalComputedCost[nVariables + 1];
totalComputedCost[0] <== 0;

component lt[nVariables];
component gt[nVariables];
component absoluteDelta[nVariables];
component isLessThanCostMax;

for (var i = 0; i < nVariables; i++) {
// 1. Verify Bounding Box Limits: repairedState[i] >= originalState[i] + minRange
lt[i] = LessThan(64);
lt[i].in[0] <== repairedState[i];
lt[i].in[1] <== originalState[i] + minRanges[i];
lt[i].out === 0; // Must NOT be less than minimum allowed bound

// 2. Verify Bounding Box Limits: repairedState[i] <= originalState[i] + maxRange
gt[i] = GreaterThan(64);
gt[i].in[0] <== repairedState[i];
gt[i].in[1] <== originalState[i] + maxRanges[i];
gt[i].out === 0; // Must NOT be greater than maximum allowed bound

// 3. Accumulate Cost Footprint
// Absolute delta computation proxy: (repaired - original)^2 variant or simple sign gating
// For simplicity here, assuming absolute value logic is handled via custom sign bit templates
signal delta <== repairedState[i] - originalState[i];

// Accumulate total cost step by step
totalComputedCost[i+1] <== totalComputedCost[i] + (delta * variableCosts[i]);
}

// 4. Enforce global cost constraints
isLessThanCostMax = LessEqThan(64);
isLessThanCostMax.in[0] <== totalComputedCost[nVariables];
isLessThanCostMax.in[1] <== maxTotalCost;
isLessThanCostMax.out === 1; // Enforce that cost check passes

isValidRepair <== isLessThanCostMax.out;
}

component main {public [originalStateHash, policyInvariantsHash, maxTotalCost]} = StateRepairVerifier(5);

export async function generateRepairProof(payload: ZKInputPayload) {
const SCALE = 100000; // Fixed-point conversion multiplier

// Map float values to scaled circuit integer inputs
const circuitInputs = {
originalState: payload.originalState.map(v => Math.round(v * SCALE)),
